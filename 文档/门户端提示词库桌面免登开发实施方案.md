# 门户端提示词库桌面免登开发实施方案

## 1. 文档范围

本文档仅描述以下门户系统需要完成的工作：

```text
agent.xianmaec.com
cv.xianmaec.com
门户用户系统
门户会话系统
门户Redis或等效缓存
```

XMAI Studio 客户端和 XMAI 身份校验服务视为外部系统。门户只需要按照约定接口与它们联调。

## 2. 建设目标

已经登录 XMAI Studio 的钉钉用户点击“提示词库”后，应完成无感免登：

```text
XMAI Studio
→ agent门户桌面免登接口
→ XMAI身份校验
→ 门户签发一次性ticket
→ cv消费ticket
→ 建立门户会话
→ 固定进入/prompts
```

用户体验要求：

```text
不再次扫码
不再次打开钉钉授权页
不要求输入门户账号密码
不进入门户首页
最终固定进入/prompts
```

## 3. 当前故障

当前接口：

```http
POST https://agent.xianmaec.com/api/portal/auth/desktop
```

当前返回：

```json
{
  "code": "SESSION_EXPIRED",
  "message": "门户会话已失效"
}
```

原因：请求头中的 Bearer 令牌属于 XMAI 桌面会话，不是门户 accessToken。当前接口错误地复用了门户登录鉴权中间件。

门户需要把该接口改成独立的桌面 SSO 入口：先向 XMAI 身份校验服务验证令牌，再创建门户一次性 ticket。

## 4. 设计原则

### 4.1 身份来源

```text
XMAI负责证明“当前请求是谁”以及“该用户是否允许使用”
门户负责建立自己的用户关联和登录会话
cv负责消费一次性ticket并进入提示词页面
```

### 4.2 唯一身份键

门户用户与钉钉身份必须使用以下组合进行唯一匹配：

```text
corpId + dingtalkUserId
```

不得使用以下字段作为唯一匹配依据：

```text
昵称
真实姓名
手机号
邮箱
部门名称
```

这些资料会发生变化，只能作为展示信息。

### 4.3 会话隔离

XMAI 桌面令牌不能直接成为门户令牌。正确转换方式：

```text
XMAI桌面令牌
→ XMAI服务端验证
→ 门户一次性ticket
→ 门户自身会话
```

### 4.4 最小暴露

```text
桌面令牌不得出现在URL
桌面令牌不得写入日志
长期门户accessToken不得出现在跳转URL
一次性ticket必须短期有效且只能使用一次
```

## 5. 推荐架构

推荐使用“不透明随机 ticket + Redis 原子消费”方案。

选择原因：

```text
实现简单
容易撤销
天然支持一次性消费
不需要在URL中放用户资料
不需要让cv持有XMAI桌面令牌
agent和cv之间只共享短期ticket
```

不推荐直接在 URL 中传 JWT 或长期 accessToken。即便使用签名 JWT，也需要额外的防重放存储，复杂度更高。

## 6. 门户端完整时序

```text
客户端                       agent后端                     XMAI校验服务                 cv后端
   |                            |                              |                           |
   | POST /auth/desktop         |                              |                           |
   | Bearer XMAI桌面令牌         |                              |                           |
   |--------------------------->|                              |                           |
   |                            | 校验参数和请求频率             |                           |
   |                            | POST /session/verify          |                           |
   |                            |----------------------------->|                           |
   |                            |                              | 校验令牌与用户权限          |
   |                            |<-----------------------------|                           |
   |                            | verified=true                 |                           |
   |                            | 查找或创建门户用户              |                           |
   |                            | 生成ticket并写入Redis           |                           |
   |<---------------------------|                              |                           |
   | 返回cv免登URL               |                              |                           |
   |------------------------------------------------------------------------------------->|
   |                            |                              |       GETDEL ticket       |
   |                            |                              |       创建门户会话         |
   |<-------------------------------------------------------------------------------------|
   |                                  302 /prompts                                        |
```

## 7. agent 后端改造

### 7.1 接口位置

保留现有地址：

```http
POST /api/portal/auth/desktop
```

路由必须位于门户普通 accessToken 鉴权中间件之前。

该接口不能要求：

```text
门户Cookie
门户accessToken
已登录门户会话
CSRF Token
```

该接口仍需执行：

```text
HTTPS
参数校验
请求频率限制
XMAI服务端校验
来源和目标入口限制
安全日志
```

### 7.2 客户端请求格式

```http
POST /api/portal/auth/desktop HTTP/1.1
Authorization: Bearer <XMAI桌面会话令牌>
Content-Type: application/json
Accept: application/json
```

```json
{
  "DTUserId": "钉钉企业userid",
  "corpId": "钉钉企业corpId",
  "source": "XM_PORTAL",
  "entry": "prompts"
}
```

### 7.3 请求校验

| 字段 | 规则 |
|---|---|
| `Authorization` | 必须是非空 Bearer 令牌 |
| `DTUserId` | 必填，字符串，建议最长 128 字符 |
| `corpId` | 必填，字符串，建议最长 128 字符 |
| `source` | 必须严格等于 `XM_PORTAL` |
| `entry` | 必须严格等于 `prompts` |
| 请求体 | 建议最大 4 KB |

不得接受：

```text
redirectUrl
returnUrl
callbackUrl
任意目标域名
客户端提交的用户角色
客户端提交的管理员标志
```

### 7.4 Bearer 令牌处理

门户只在当前请求内暂存桌面令牌，用于调用 XMAI 校验服务。

禁止：

```text
保存到门户数据库
保存到Redis
写入日志
写入错误堆栈
返回给浏览器
拼接到URL
```

建议统一日志脱敏中间件过滤：

```text
Authorization
Cookie
Set-Cookie
desktopSessionToken
accessToken
ticket
```

## 8. 调用 XMAI 身份校验服务

### 8.1 外部依赖接口

XMAI 侧将提供类似以下接口，最终地址以联调配置为准：

```http
POST /api/integrations/prompt-portal/session/verify
```

请求体：

```json
{
  "desktopSessionToken": "客户端Bearer令牌",
  "dingtalkUserId": "客户端DTUserId",
  "corpId": "客户端corpId",
  "audience": "prompt-portal"
}
```

### 8.2 服务间鉴权

门户后端环境变量建议配置：

```text
XMAI_VERIFY_BASE_URL
XMAI_INTEGRATION_KEY
XMAI_INTEGRATION_SECRET
XMAI_VERIFY_TIMEOUT_MS=5000
```

请求头：

```http
X-XMAI-Integration-Key: <专用Key>
X-XMAI-Timestamp: <Unix时间戳>
X-XMAI-Nonce: <随机字符串>
X-XMAI-Signature: <HMAC-SHA256签名>
```

签名原文：

```text
timestamp + "\n" + nonce + "\n" + 原始JSON请求体
```

### 8.3 调用策略

```text
连接和总请求超时建议3至5秒
只对网络错误最多重试1次
401、403和400不得重试
重试必须复用原始业务参数，但重新生成timestamp、nonce和签名
验证成功后不得再次调用，以免重复生成门户用户或ticket
```

### 8.4 XMAI 成功响应

```json
{
  "code": "0",
  "message": "OK",
  "data": {
    "verified": true,
    "userId": "XMAI用户ID",
    "dingtalkUserId": "钉钉userid",
    "corpId": "钉钉企业corpId",
    "nickname": "钉钉昵称",
    "department": "所属部门",
    "status": 1
  }
}
```

门户必须再次比较：

```text
响应dingtalkUserId等于客户端DTUserId
响应corpId等于客户端corpId
verified严格等于true
status严格等于1
```

不得只根据 HTTP 200 判断登录成功。

## 9. 门户用户关联

### 9.1 查询规则

```sql
WHERE dingtalk_corp_id = :corpId
  AND dingtalk_user_id = :dingtalkUserId
```

建议建立唯一索引：

```sql
UNIQUE (dingtalk_corp_id, dingtalk_user_id)
```

实际表名和字段名根据门户现有数据库调整。

### 9.2 已存在用户

```text
复用原用户ID
更新钉钉昵称等展示资料
更新部门等非权限资料
保留用户已有提示词、收藏和业务数据
不创建重复账号
```

### 9.3 不存在用户

为了保证 XMAI 授权用户首次进入即可使用，推荐创建最小门户账号：

```text
身份来源标记为XMAI_DESKTOP_SSO
绑定corpId和dingtalkUserId
昵称使用XMAI验证结果
部门使用XMAI验证结果
使用门户默认普通用户角色
不生成可登录的默认密码
```

自动创建必须发生在 XMAI 校验成功之后。

如果门户业务不允许自动创建，应返回明确错误 `PORTAL_USER_NOT_FOUND`，不能回退到二次钉钉登录。

### 9.4 异常数据

如果同一 `corpId + dingtalkUserId` 匹配多个门户账号：

```text
拒绝登录
返回PORTAL_IDENTITY_DUPLICATED
记录请求ID和重复用户ID
由管理员清理数据
```

不得随机选择其中一个账号。

### 9.5 用户状态

以下条件建议同时满足：

```text
XMAI验证通过
门户用户没有被删除
门户用户没有被禁用
门户用户没有被锁定
```

## 10. 一次性 ticket 设计

### 10.1 ticket 生成

```text
使用密码学安全随机数生成器
随机数据不少于32字节
使用Base64URL或十六进制编码
有效期建议60秒，最长不超过120秒
```

示例逻辑：

```text
ticket = base64url(randomBytes(32))
ticketHash = SHA256(ticket)
```

### 10.2 Redis 数据

建议 Key：

```text
xmai:prompt-sso:ticket:<ticketHash>
```

建议 Value：

```json
{
  "portalUserId": "门户用户ID",
  "dingtalkUserId": "钉钉userid",
  "corpId": "企业corpId",
  "entry": "prompts",
  "issuedAt": "ISO时间",
  "requestId": "请求ID"
}
```

写入要求：

```text
SET key value EX 60 NX
```

Redis 只保存 ticket 哈希，不能保存 ticket 明文或 XMAI 桌面令牌。

### 10.3 返回客户端

```json
{
  "code": "0",
  "message": "OK",
  "data": {
    "url": "https://cv.xianmaec.com/dingtalk-sso?source=XM_PORTAL&entry=prompts&ticket=<ticket>"
  },
  "requestId": "req-xxxx"
}
```

URL 必须由门户后端固定构造，不能使用客户端提交的回跳地址。

## 11. cv 后端改造

### 11.1 ticket 消费入口

```http
GET /dingtalk-sso?source=XM_PORTAL&entry=prompts&ticket=<ticket>
```

### 11.2 参数校验

```text
source严格等于XM_PORTAL
entry严格等于prompts
ticket格式和长度正确
不存在额外redirectUrl
```

### 11.3 原子消费

处理步骤：

```text
计算SHA-256(ticket)
使用Redis GETDEL读取并删除
不存在时返回ticket无效或过期
检查entry严格等于prompts
查询门户用户最新状态
建立门户会话
```

如果 Redis 版本不支持 `GETDEL`，必须使用 Lua 脚本完成原子读取和删除。

禁止使用普通 `GET` 后再 `DEL`，否则并发请求可能重复消费同一 ticket。

### 11.4 agent 与 cv 的共享方式

优先方案：

```text
agent和cv共用同一个Redis逻辑库和Key前缀
```

备选方案：

```text
cv通过服务间签名调用agent的内部ticket消费接口
```

不建议把 ticket 写入关系数据库后轮询，性能和清理复杂度都更高。

### 11.5 建立门户会话

推荐使用 Cookie：

```text
HttpOnly=true
Secure=true
SameSite=Lax
Path=/
```

Cookie 应由 `cv.xianmaec.com` 自己设置，不依赖 `agent.xianmaec.com` 跨域写入。

如果现有系统使用 `sessionStorage.XM_PORTAL_ACCESS_TOKEN`，可以在 cv 的可信中转页面写入门户 token，然后立即跳转 `/prompts`。长期 token 仍不得放在 URL。

### 11.6 最终跳转

```http
HTTP/1.1 302 Found
Location: /prompts
Cache-Control: no-store
```

## 12. CORS、CSRF 与浏览器约束

桌面免登请求由 Electron 主进程发出，不依赖浏览器 CORS。

门户接口应当：

```text
允许没有Origin请求头的合法桌面请求
不依赖门户Cookie
不要求CSRF Token
不配置Access-Control-Allow-Origin: *来解决问题
使用XMAI令牌校验和服务间验证建立信任
```

`/dingtalk-sso` 是浏览器导航入口，不需要开放跨域 Ajax。

## 13. 请求频率和抗攻击

建议限制：

```text
单IP每分钟最多30次桌面免登请求
单corpId + DTUserId每分钟最多10次
单ticket只能消费1次
连续失败触发短期冷却
请求体最大4KB
XMAI校验超时不超过5秒
```

频率限制只用于防止接口攻击，不限制用户正常使用次数。

## 14. 错误规范

| HTTP状态 | 错误码 | 场景 |
|---:|---|---|
| 400 | `INVALID_REQUEST` | 请求参数错误 |
| 400 | `INVALID_SOURCE` | source不是XM_PORTAL |
| 400 | `INVALID_ENTRY` | entry不是prompts |
| 401 | `XMAI_SESSION_EXPIRED` | XMAI桌面会话失效 |
| 403 | `XMAI_USER_MISMATCH` | userid或corpId不一致 |
| 403 | `XMAI_USER_DISABLED` | XMAI用户被禁用 |
| 403 | `XMAI_PERMISSION_DENIED` | XMAI或MAPMS权限拒绝 |
| 403 | `PORTAL_USER_DISABLED` | 门户用户被禁用 |
| 404 | `PORTAL_USER_NOT_FOUND` | 门户禁止自动创建且用户不存在 |
| 409 | `PORTAL_IDENTITY_DUPLICATED` | 同一钉钉身份关联多个门户账号 |
| 409 | `TICKET_USED` | ticket已经使用 |
| 410 | `TICKET_EXPIRED` | ticket已经过期 |
| 429 | `RATE_LIMITED` | 请求过于频繁 |
| 503 | `XMAI_VERIFY_UNAVAILABLE` | XMAI校验服务不可用 |

统一错误格式：

```json
{
  "code": "XMAI_SESSION_EXPIRED",
  "message": "XMAI桌面会话已失效，请重新登录客户端",
  "requestId": "req-xxxx"
}
```

不得把内部堆栈、数据库错误、令牌内容或服务间地址返回客户端。

## 20. 灰度和回滚

使用开关：

```text
XMAI_DESKTOP_SSO_ENABLED=false
```

关闭开关后：

```text
/api/portal/auth/desktop返回功能暂未开放
原有门户登录不受影响
原有钉钉免登不受影响
已登录门户用户不被强制退出
```

回滚步骤：

```text
关闭桌面免登开关
停止签发新ticket
等待现有ticket自然过期
恢复上一版agent和cv服务
保留门户用户和提示词业务数据
```

