# 先马·AI Studio 自动更新使用说明

## 当前规则

统一版本使用：

```text
显示版本：1.0.2
内部版本：1.0.2
更新通道：stable-v2
```

后续每次同步递增：

```text
1.0.3 / 1.0.3
1.0.4 / 1.0.4
```

旧客户端仍在 `stable` 通道。新客户端只检查 `stable-v2`，不会把旧通道中的更高数字误判为更新。

## 第一次迁移

所有用户需要执行一次人工重装：

1. 正常退出软件。
2. 使用 Windows 设置卸载旧版。
3. 不使用第三方卸载清理工具。
4. 不手动删除 `%APPDATA%` 或 `C:\ProgramData\XianmaAIStudio`。
5. 安装 `先马·AI Studio Setup 1.0.2 统一版本重装版.exe`。
6. 打开软件并检查钉钉登录、历史会话、技能和文件。

卸载只删除 `C:\Program Files\先马·AI Studio` 中的软件文件，历史数据和公共配置会保留。

## 用户如何检查更新

1. 打开软件设置页。
2. 点击“检查更新”。
3. 有新版本时查看版本号、发布时间、安装包大小、更新标题和更新内容。
4. 点击“立即更新”。
5. 软件完成下载、校验和安装后自动重新打开。

软件启动后也会自动检查，并按周期继续检查。普通用户看不到服务器地址、内部版本、模型 Key 或签名信息。

## 更新过程

```text
检查 stable-v2
→ 显示更新内容
→ 后台分片下载
→ 校验大小和 SHA-256
→ 校验更新清单签名
→ 备份对话数据
→ 启动覆盖安装
→ 自动重启
→ 继续使用原数据目录
```

下载中断后可继续。缓存安装包通过大小、SHA-256 和签名检查时直接复用；缓存损坏时重新下载。

## 发布新版本

更新后台：

[打开更新后台](http://47.96.184.148/xianma-updates/admin)

发布步骤：

1. 使用本机安全保存的管理密码登录后台。
2. 选择通道 `stable-v2`。
3. 选择平台 `win32` 和架构 `x64`。
4. 填写显示版本和内部版本，两者保持一致。
5. 填写更新标题和更新内容。
6. 选择真实的新 EXE 安装包。
7. 一般不勾选“强制更新”。
8. 点击“上传并发布”。

后台按“通道 + 平台 + 架构 + 内部版本”判断重复。`stable-v2` 首个版本是 `1.0.2`，下一版是 `1.0.3`。

大安装包使用分片上传。网络中断后重新选择同一个文件，可以复用已完成的分片。

## 撤回与永久删除

撤回错误版本：

1. 在后台找到版本。
2. 点击“撤回”。
3. 撤回后新客户端不再下载该版本。

撤回不会让已升级用户自动降级。修复问题时应发布更高版本。

永久删除：

1. 先撤回版本。
2. 点击“永久删除”。
3. 二次确认后，服务器安装文件被真正删除。

发布中或草稿状态不能直接永久删除。删除不可恢复，审计记录仍保留。

## 为什么历史数据不会丢

保留位置：

```text
%APPDATA%\XianmaAIStudio\user-data-route.json
%APPDATA%\xianma-ai-studio
%APPDATA%\xianma-centaur-desktop
C:\ProgramData\XianmaAIStudio
```

保护措施：

- 安装器只覆盖 Program Files 中的软件文件。
- 卸载器不删除 AppData 和 ProgramData。
- 新版读取稳定数据路由并兼容旧目录。
- 自动更新前保存对话备份。
- 更新失败后再次安装仍使用原数据目录。

第三方强力卸载、磁盘清理或手动删除数据目录不在保护范围内。

## 构建下一版本

在工程目录执行：

```powershell
npm run build
```

构建前必须同步修改：

```text
package.json
electron/update-config.json
electron-builder.<版本>.json
```

检查内容：

```text
package/version = 显示版本 = 内部版本
channel = stable-v2
appId 不变
产品名 = 先马·AI Studio
```

不能只修改 EXE 文件名。更新判断读取安装包内部配置。

## 1.0.2 到 1.0.3 测试

1. 在测试电脑安装统一版本 `1.0.2`。
2. 创建会话、技能、图片和文件。
3. 构建真实 `1.0.3 / 1.0.3 / stable-v2` 安装包。
4. 在后台发布 `stable-v2 / win32 / x64 / 1.0.3`。
5. 在 `1.0.2` 设置页点击“检查更新”。
6. 查看新版本和更新内容。
7. 执行更新并等待软件自动重启。
8. 验证版本为 `1.0.3`，历史数据完整。

## 服务器位置

```text
服务目录：/opt/xianma-update-service
发布数据：/opt/xianma-update-service/data
服务容器：xianma-update-service
Nginx 路径：/xianma-updates/
```

常用排查：

```bash
cd /opt/xianma-update-service
docker compose ps
docker compose logs --tail 100
curl http://127.0.0.1:18091/health
```
