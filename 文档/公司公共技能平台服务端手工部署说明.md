# 公司公共技能平台服务端手工部署说明

## 1. 本次交付边界

- 本次只生成本地客户端安装包和服务端部署文件。
- 不自动连接服务器。
- 不自动上传安装包。
- 不自动发布 `1.0.4` 更新版本。
- 用户试用通过后，再手工部署服务端并上传安装包。

## 2. 部署前备份

服务器建议目录：

```text
/opt/xianma-update-service
```

部署前必须备份：

```text
/opt/xianma-update-service/data
/opt/xianma-update-service/secrets
/opt/xianma-update-service/.env
/opt/xianma-update-service/docker-compose.yml
```

`data` 包含版本、用户统计、技能提交、公司技能和匿名统计。`secrets` 包含更新及公司技能签名私钥。不要删除、覆盖或重新生成现有签名私钥，否则现有客户端无法验证新包。

## 3. 需要上传的文件

将交付目录中的服务端升级包上传到临时目录，解压后只覆盖：

```text
server.js
company-skills.js
public/
docker-compose.yml
.env.example
```

不要上传或覆盖本地测试数据，不要覆盖服务器的 `data/`、`secrets/` 和 `.env`。

## 4. 设置后台密码

后台密码不写在源码和安装包中，只保存在服务器：

```text
/opt/xianma-update-service/.env
```

使用文本编辑器修改：

```text
UPDATE_ADMIN_TOKEN=填写本次确定的新后台密码
```

保存后重启服务才会生效。不要把 `.env` 发给普通用户，也不要提交到代码仓库。

## 5. 检查其他环境变量

至少确认：

```text
UPDATE_PUBLIC_BASE_URL
MAPMS_BASE_URL
MAPMS_API_KEY
MAPMS_API_SECRET
MAPMS_ADMIN_BASE_URL
MAPMS_ADMIN_USERNAME
MAPMS_ADMIN_PASSWORD
DINGTALK_APP_KEY
DINGTALK_APP_SECRET
TELEMETRY_ALLOWED_CORP_ID
ADMIN_FRAME_ANCESTORS
```

管理后台需要嵌入其他平台时，在 `ADMIN_FRAME_ANCESTORS` 中加入受控来源，不要使用任意来源通配符。

## 6. 手工部署

进入服务目录后执行：

```bash
cd /opt/xianma-update-service
docker compose config
docker compose up -d --force-recreate
docker compose ps
docker compose logs --tail=100
```

如果 `docker compose config` 报环境变量缺失，先修正 `.env`，不要继续启动。

## 7. 部署后验证

1. 打开更新管理后台，使用新后台密码登录。
2. 确认“版本发布”和“软件使用统计”仍可打开。
3. 打开“技能审核”，确认页面可加载。
4. 使用测试钉钉账号登录 1.0.4 客户端。
5. 创建一个低风险测试技能并提交。
6. 后台批准后，在公司技能库安装。
7. 在对话中调用，确认结果正常。
8. 检查匿名调用统计，不应出现用户身份和提示词。
9. 下架测试技能，重启客户端确认技能停用。

## 8. 服务器数据位置

```text
/data/skills/submissions/    原始提交包
/data/skills/public/         已审核发布包
/data/skill-submissions.json 审核记录
/data/company-skills.json    公司技能目录
/data/skill-usage.json       匿名使用统计
```

Docker 中 `/data` 映射到现有持久化目录。升级和重启不能清空该目录。

## 9. 回退方法

如果服务端升级后异常：

1. 停止当前容器。
2. 恢复部署前备份的代码和 `docker-compose.yml`。
3. 保留最新 `data/`，不要直接删除用户提交。
4. 使用备份副本对比新增数据结构后再决定是否恢复旧数据。
5. 重新启动并检查日志。

公司技能服务未部署时，1.0.4 的原有对话、本地技能、在线技能、文件、文档和本机操作仍可使用；公司技能相关页面会显示服务暂不可用。

## 10. 安装包发布

用户试用通过后，才在后台手工上传：

```text
显示版本：1.0.4
内部版本：1.0.4
通道：stable-v2
平台：win32
架构：x64
```

上传前核对安装包 SHA-256。不要重复上传相同“通道 + 平台 + 架构 + 内部版本”。
