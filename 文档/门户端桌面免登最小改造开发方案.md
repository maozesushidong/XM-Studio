# 门户端提示词库桌面免登唯一实施方案

> 状态：最终方案，2026-08-24 已按线上门户代码、XMAI 客户端代码和本地服务端自动化测试核验。门户开发只使用本文件，其他同主题文档均为历史草案。

## 1. 目标

已登录 XMAI Studio 的用户点击“提示词库”后：

```text
不再次扫码
不再次输入账号密码
不再次进行钉钉授权
最终固定进入 https://cv.xianmaec.com/prompts
```

## 2. 最终结论

本方案可实施，采用现有门户链路的最小改造：

```text
XMAI客户端
  -> POST agent /api/portal/auth/desktop
  -> agent调用XMAI会话验证接口
  -> agent复用现有门户用户匹配和accessToken签发逻辑
  -> 客户端调用现有entries接口
  -> 客户端调用现有PROMPT_LIBRARY launch接口
  -> cv消费现有ticket
  -> /prompts
```

门户不需要重做网页，不需要修改原钉钉登录入口，也不需要先改 cv。优先只修改 `agent.xianmaec.com` 的一个后端接口：

```http
POST /api/portal/auth/desktop
```

## 3. 已核验事实

### 3.1 线上门户现状

2026-08-24 已检查线上门户前端资源，现有接口及格式为：

```http
GET  /api/portal/session
POST /api/portal/auth/dingtalk
GET  /api/portal/entries
POST /api/portal/entries/:code/launch
```

线上前端的真实行为：

```text
/api/portal/auth/dingtalk 返回根级 accessToken
accessToken 保存到 sessionStorage 的 XM_PORTAL_ACCESS_TOKEN
后续请求使用 Authorization: Bearer <门户accessToken>
/api/portal/entries 返回根级入口数组
/api/portal/entries/:code/launch 返回根级 url
PROMPT_LIBRARY 已存在
PROMPT_LIBRARY 的目标是 cv.xianmaec.com/dingtalk-sso?source=XM_PORTAL&entry=prompts
```

### 3.2 当前故障

线上接口已经存在：

```http
POST /api/portal/auth/desktop
```

但真实客户端调用返回：

```json
{
  "code": "SESSION_EXPIRED",
  "message": "门户会话已失效"
}
```

原因是该接口当前把 XMAI 桌面令牌当成了门户 accessToken。XMAI 桌面令牌必须先交给 XMAI 服务端验证，不能直接使用门户普通鉴权中间件解析。

### 3.3 XMAI 客户端已具备的能力

客户端已经完整支持：

```text
调用 /api/portal/auth/desktop
接收门户 accessToken
使用 Bearer accessToken 调用 /api/portal/entries
优先选择 code = PROMPT_LIBRARY
调用 /api/portal/entries/PROMPT_LIBRARY/launch
校验 cv 域名、/dingtalk-sso、source、entry 和 ticket
等待最终路径严格等于 /prompts
```

客户端无需为本方案再次改协议。

### 3.4 XMAI 服务端已具备的能力

本地源码已经实现并通过自动化测试：

```http
POST /api/integrations/prompt-portal/session/verify
```

该接口会验证：

```text
门户服务间HMAC签名
时间戳和一次性Nonce
XMAI桌面会话令牌
请求corpId与桌面会话corpId一致
请求dingtalkUserId与桌面会话userid一致
MAPMS用户当前处于启用状态
```

联调前需要由 XMAI 方部署该接口，并单独提供联调地址、Integration Key 和 Integration Secret。接口协议已经固定，不再修改字段。

## 4. 门户唯一改动

### 4.1 客户端请求

客户端会发送：

```http
POST https://agent.xianmaec.com/api/portal/auth/desktop
Authorization: Bearer <XMAI桌面会话令牌>
Content-Type: application/json
Accept: application/json
```

```json
{
  "DTUserId": "钉钉企业userid",
  "corpId": "钉钉企业corpId",
  "source": "XM_PORTAL",
  "entry": "prompts"
}
```

### 4.2 路由要求

`/api/portal/auth/desktop` 必须放在门户普通 accessToken 鉴权中间件之前。

该接口不能要求：

```text
门户accessToken
门户Cookie
已登录门户会话
CSRF Token
第二次钉钉授权码
```

该接口只接受：

```text
source = XM_PORTAL
entry = prompts
非空Bearer桌面令牌
非空DTUserId
非空corpId
```

不得接受客户端指定 `redirectUrl`、角色、管理员状态或门户用户 ID。

### 4.3 门户调用 XMAI 验证接口

门户从客户端 Authorization 读取桌面令牌，然后调用：

```http
POST <XMAI_VERIFY_BASE_URL>/api/integrations/prompt-portal/session/verify
Content-Type: application/json
X-XMAI-Integration-Key: <门户专用Key>
X-XMAI-Timestamp: <13位Unix毫秒时间戳>
X-XMAI-Nonce: <16至128字符随机Base64URL字符串>
X-XMAI-Signature: <小写十六进制HMAC-SHA256>
```

请求体：

```json
{
  "desktopSessionToken": "客户端Bearer令牌",
  "dingtalkUserId": "客户端DTUserId",
  "corpId": "客户端corpId",
  "audience": "prompt-portal"
}
```

### 4.4 签名算法

必须先生成最终发送的原始 JSON 字符串 `rawBody`，再计算：

```text
bodySha256 = SHA256_HEX(rawBody)

canonical =
  "POST" + "\n" +
  "/api/integrations/prompt-portal/session/verify" + "\n" +
  timestamp + "\n" +
  nonce + "\n" +
  bodySha256

signature = HMAC_SHA256_HEX(integrationSecret, canonical)
```

注意：签名完成后必须发送同一个 `rawBody`，不能再次序列化，否则摘要可能变化。

Node.js 参考代码：

```js
const crypto = require("crypto");

function signXmaiRequest(payload, integrationSecret) {
  const pathname = "/api/integrations/prompt-portal/session/verify";
  const rawBody = JSON.stringify(payload);
  const timestamp = String(Date.now());
  const nonce = crypto.randomBytes(18).toString("base64url");
  const bodySha256 = crypto.createHash("sha256").update(rawBody).digest("hex");
  const canonical = `POST\n${pathname}\n${timestamp}\n${nonce}\n${bodySha256}`;
  const signature = crypto.createHmac("sha256", integrationSecret)
    .update(canonical)
    .digest("hex");
  return { rawBody, timestamp, nonce, signature };
}
```

### 4.5 XMAI 验证成功响应

```json
{
  "code": "0",
  "message": "OK",
  "data": {
    "verified": true,
    "userId": "XMAI用户ID",
    "dingtalkUserId": "钉钉企业userid",
    "corpId": "钉钉企业corpId",
    "nickname": "钉钉昵称",
    "department": "钉钉企业部门",
    "status": 1
  },
  "requestId": "xmai-xxxx"
}
```

门户必须同时检查：

```text
HTTP状态为200
code严格等于字符串"0"
data.verified严格等于true
data.status严格等于1
响应dingtalkUserId等于客户端DTUserId
响应corpId等于客户端corpId
```

任一条件不满足都不能签发门户 accessToken。

## 5. 门户用户处理

门户必须复用现有 `/api/portal/auth/dingtalk` 登录成功后的同一套用户匹配或创建逻辑，不另写一套用户表逻辑。

唯一身份键：

```text
corpId + dingtalkUserId
```

禁止使用昵称、真实姓名、部门、手机号或邮箱作为唯一键。

处理规则：

```text
已有用户：复用原门户用户ID和原有提示词数据
没有用户：调用现有钉钉登录的“查找或创建用户”方法创建一次
用户禁用或锁定：拒绝签发Token
同一钉钉身份匹配多个用户：拒绝并清理重复数据
昵称或部门变化：只更新展示资料，不创建新用户
```

数据库应具备等价唯一约束：

```sql
UNIQUE (dingtalk_corp_id, dingtalk_user_id)
```

如果现有门户只有 `dingtalk_user_id` 且门户只服务一个固定企业，可以沿用现有唯一字段，但不能用昵称匹配。

## 6. 门户 Token 签发

必须复用现有 `/api/portal/auth/dingtalk` 使用的 Token 服务，例如现有的：

```text
issueAccessToken(portalUser)
createPortalSession(portalUser)
generateLoginToken(portalUser)
```

实际方法名以门户源码为准。桌面免登 Token 与原钉钉登录 Token 必须保持：

```text
同一种格式
同一种签名算法
同一个有效期策略
同一套角色与入口权限
可以调用/session、/entries和/launch
```

门户成功响应使用线上现有根级格式：

```json
{
  "accessToken": "门户签发的accessToken"
}
```

客户端也兼容 `data.accessToken`，但本次应保持门户现有根级格式，减少改动。

## 7. 客户端后续调用

门户返回 accessToken 后，客户端自动执行：

```http
GET /api/portal/entries
Authorization: Bearer <门户accessToken>
```

线上现有返回为根级数组，必须包含：

```json
[
  {
    "code": "PROMPT_LIBRARY",
    "name": "提示词库",
    "status": "ENABLED",
    "launchUrl": "https://cv.xianmaec.com/dingtalk-sso?source=XM_PORTAL&entry=prompts"
  }
]
```

然后客户端执行：

```http
POST /api/portal/entries/PROMPT_LIBRARY/launch
Authorization: Bearer <门户accessToken>
```

线上现有成功格式：

```json
{
  "url": "https://cv.xianmaec.com/dingtalk-sso?source=XM_PORTAL&entry=prompts&ticket=一次性票据"
}
```

客户端只接受：

```text
origin = https://cv.xianmaec.com
path = /dingtalk-sso
source = XM_PORTAL
entry = prompts
ticket非空
```

最终必须跳转到：

```text
https://cv.xianmaec.com/prompts
```

## 8. 门户接口伪代码

```text
POST /api/portal/auth/desktop

desktopToken = parseBearerToken(request.Authorization)
assert request.body.source == "XM_PORTAL"
assert request.body.entry == "prompts"
assert DTUserId and corpId are present

verified = callXmaiVerify({
  desktopSessionToken: desktopToken,
  dingtalkUserId: request.body.DTUserId,

assert verified.code == "0"
assert verified.data.verified == true
assert verified.data.status == 1
assert verified.data.dingtalkUserId == request.body.DTUserId

  corpId: verified.data.corpId,
  dingtalkUserId: verified.data.dingtalkUserId,
  nickname: verified.data.nickname,
  department: verified.data.department
})

assert portalUser is enabled and not locked
accessToken = existingPortalTokenService.issue(portalUser)
return 200 { accessToken }
```

## 9. 错误处理

门户对客户端统一返回：

| HTTP | code | 场景 |
|---:|---|---|
| 400 | `INVALID_REQUEST` | 请求参数错误 |
| 401 | `XMAI_SESSION_EXPIRED` | 桌面会话失效 |
| 403 | `XMAI_USER_MISMATCH` | 钉钉身份不一致 |
| 403 | `XMAI_PERMISSION_DENIED` | MAPMS 权限拒绝 |
| 403 | `PORTAL_USER_DISABLED` | 门户用户禁用或锁定 |
| 409 | `PORTAL_IDENTITY_DUPLICATED` | 门户身份重复 |
| 429 | `RATE_LIMITED` | 请求过于频繁 |
| 503 | `XMAI_VERIFY_UNAVAILABLE` | XMAI 验证服务不可用 |

统一格式：

```json
{
  "code": "XMAI_SESSION_EXPIRED",
  "message": "XMAI桌面会话已失效，请重新登录客户端",
  "requestId": "portal-xxxx"
}
```

不得把 XMAI 服务端错误堆栈、内部地址、令牌或 Secret 返回客户端。

## 10. 安全要求

```text
XMAI桌面令牌不得写数据库、Redis、URL或日志
门户accessToken不得出现在URL或日志
Integration Secret只放门户服务端环境变量
Authorization、Cookie、Token、Signature必须日志脱敏
门户到XMAI验证服务使用HTTPS
XMAI验证调用超时5秒
400、401、403不重试
网络错误最多重试1次，并生成新的timestamp和nonce
```

XMAI 验证接口已启用两分钟签名窗口和 Nonce 防重放。门户服务器时间必须使用 NTP 保持准确。

## 14. 验收标准

以下条件必须全部满足：

```text
/api/portal/auth/desktop不再把XMAI令牌当门户令牌
XMAI校验失败时门户绝不签发accessToken
门户按钉钉唯一身份复用或创建用户，不产生重复账号
门户Token可调用session、entries和launch
客户端没有第二次登录
最终固定进入/prompts
URL和日志中没有桌面令牌、门户Token或Secret
MAPMS禁用用户不能进入
门户原有登录流程不受影响
```

## 15. 部署与回滚

部署顺序：

```text
1. XMAI方先部署验证接口
2. XMAI方提供联调Base URL、Key和Secret
3. 门户测试环境部署desktop接口改动
4. 双方完成接口与真实客户端联调
5. 确认无二次登录且进入/prompts
6. 门户生产环境灰度开启
7. 回归原门户登录
8. 通过后再构建XMAI正式安装包
```

门户应保留开关：

```text
XMAI_DESKTOP_SSO_ENABLED=false
```

关闭开关只停用桌面免登入口，不删除用户，不清除门户会话，不影响原网页及钉钉登录。

## 16. 本次不采用的方案

本次不让门户新建第二套 ticket 服务，也不提前修改 cv。只有现有 `PROMPT_LIBRARY/launch` 无法为桌面免登用户生成有效 ticket 时，才另立问题单评估 cv；不能在本次开发中并行实现两套方案。
