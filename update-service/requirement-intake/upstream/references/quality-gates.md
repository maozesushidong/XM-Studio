# 需求分析质量门禁

交付前执行所有相关门禁；任一关键门禁未通过，需求保持草稿。

## 渠道门禁（CHANNEL_GATE_DIRECT_AGENT_NO_AUTO_REQ）

- 已确认当前会话是否来自钉钉业务需求机器人，而不是仅根据业务内容或项目名称推断。
- 用户与 Codex、Hermes、Claude 直接沟通时，默认未创建REQ、未写“待数智审核”、未调用需求通知脚本。
- 直接 Agent 会话只有本轮出现“纳入需求池/生成REQ/走数智审核”等明确授权时，才进入正式存档门禁。
- 渠道不明时保持不存档、不通知，并继续确认来源。
- 项目事实、PRD、决策、验收或上线写回没有被误当成新增需求档案。

## 理解门禁

- 不依赖提议方案即可说明真实问题和期望业务结果。
- 明确主要角色、具体场景、最近真实案例和当前流程。
- 能定位瓶颈；不同工作流或目标拆为独立需求分支。
- 业务人员已纠正或明确确认最终摘要。

## 追问门禁

- 每轮一个高价值主问题，最多一个紧密关联问题。
- 问题根据最新回答和最大缺口生成，不发送问卷。
- 每两到三轮区分总结：事实、假设、待确认、分歧、分支。
- 抽象说法追问真实案例；范围可能混合时用反例验证。
- 不让业务人员设计字段、页面、状态机、API 或架构。

## 项目路由与知识库门禁

- 输入已经指向现有项目时，已读取 `需求项目路由与知识库映射.md`。
- 已读取项目一级事实入口和与本轮问题直接相关的模块节点；未全量扫描项目目录。
- 追问基于“现有能力与诉求的差距”，没有重复询问知识库已明确且无冲突的事实。
- 已将诉求归为“可直接使用已有能力 / 已有部分能力需要增强 / 当前无对应能力”，并用一句业务语言告知与本轮直接相关的已有能力和差距。
- 业务说“新增/增加”时，没有未经检索就假设平台不存在相关能力；相似能力已区分场景和边界。
- 检索结论已区分已上线、已确认规则、当前原型、待开发、历史版本和待确认。
- 文件日期较早或多个版本冲突时，没有用文件名中的“当前/最终”代替核验。
- 路由不明确时保持待归属确认，没有擅自创建项目或套用项目规则。
- 知识库检索没有自动触发PRD、原型、线上操作或实现。
- 保存REQ时，`knowledge_sources` 和“知识库检索记录”只包含实际读取的资料。

## 事实与证据门禁

- 区分已观察事实、业务决策、推断、假设和待确认项。
- 不编造负责人、日期、部门、数字、频率、成功标准或系统能力。
- 已有问题尽量有案例；预测机会要有证据或验证计划。
- 无法验证的系统信息明确写“待验证”。

## 范围与风险门禁

- 明确范围、非范围、异常分支和可后置扩展。
- 揭示资金、权限、隐私、安全、版权、合规和不可逆操作风险。
- 不在需求分析中承诺技术可行性或进入实现细节。

## 钉钉与敏感信息门禁

- 不自动抓取、转存完整钉钉聊天历史。
- 只有用户明确提供的聊天导出、录音、转写、截图和附件可作证据。
- 寒暄、重复试错和无价值噪声已过滤。
- 密钥、隐私和无长期保留必要的敏感信息未写入档案；必要证据已脱敏或使用受控链接。

## 档案、证据与链接门禁

- 钉钉业务需求机器人渠道在业务明确确认最终摘要后已自动创建真实需求档案；直接 Agent 会话仅在本轮明确要求入池时创建。测试、演练、不要保存或不存档时跳过。
- 正式档案位于 `02_需求与规划/01_需求池/需求档案/YYYY/`，命名为 `REQ-YYYYMMDD-序号_需求名称.md`。
- 同一天编号不重复；不能可靠确定编号时停止覆盖并标记待确认。
- 新建正式档案的 YAML 与正文状态均为“待数智审核”，业务确认记录可核验。
- 存档成功后已调用 `{NOTIFY_SERVICE}` 私信梦蝶；按REQ编号去重。
- 通知失败时档案仍保留，失败项已写入持久队列；日志和回复不含 Client ID、Secret 或 access token。
- YAML 与正文状态一致，状态变化不移动文件。
- 所有必备字段存在，未知值明确标记待确认。
- 关联项目未知时标记“待归属确认”，不擅自创建项目。
- 附件已按SHA-256查重；已有文件只链接，需求专属证据进入 `需求证据/YYYY/REQ-.../`。
- 临时副本仅在正式归档、哈希和链接验证后清理。
- 项目业务输入的 `需求入口.md` 只链接REQ、SOP和证据，没有复制需求正文。
- PRD、方案和原型位于项目产品输出，并直接链接REQ和项目需求入口。
- 产品输出已回写REQ和项目需求入口，双向链接有效。
- 未触碰 `{PROTECTED_PROJECT_DIR}`。

## 完成与路由门禁

只有渠道门禁通过、业务明确确认，且不存在会实质改变目标、范围、归属或验收的缺口时，才自动存档并将状态设为“待数智审核”。直接 Agent 会话没有本轮明确入池授权时不得自动存档。只有数智审核通过后才可改为“已确认”。

- 分析确认不等于 PRD、原型或开发授权。
- 只有用户明确要求写 PRD 才路由。
- 先马 AI 设计平台 PRD 优先 `xianma-ai-design-platform-prd`；无专用能力且明确要求通用 PRD 才用 `prd-writer`。
- “已进入项目”或“已进入PRD”只记录路由状态，不自动授权实现。
